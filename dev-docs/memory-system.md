# 记忆体系（Memory System）— 设计文档

> 日期: 2026-08-21
> 范围: 主会话（main-session）承载的系统级记忆能力
> 状态: 方案设计阶段（①用户事实层先行）

---

## 1. 人类记忆 → 系统现状对照

| 人类记忆类型 | 系统对应 | 现状 |
|------|------|------|
| 工作记忆（当前上下文） | 上下文窗口 + compaction | ✅ 基本等价 |
| 单步技能（会做一件事） | skills 按需加载 | ✅ 最接近人类的一项 |
| 流程性记忆（知道一类事怎么做 / SOP） | 零散 skill，无流程沉淀 | ⚠️ 缺：流程建模 + 情境绑定 + 进化 |
| 情景记忆（回忆经历过的事） | 会话日志（append-only） | ⚠️ 有记录，无回忆：线性日志、无索引、无聚合 |
| 语义记忆（事实与知识） | 模型参数 + workspace 文件 | ⚠️ 个人事实层缺失：重启即"失忆" |
| 前瞻记忆（记得未来要做的事） | goals（仅当前执行） | ❌ 跨会话待办无持久载体 |
| 自传体记忆（我是谁 / 经历轨迹） | 主会话摘要（雏形） | ❌ 只有委派摘要，无连贯自我叙事 |
| 元记忆（知道自己知道什么） | 无 | ❌ 无记忆清单 / 索引 |
| 遗忘（主动淘汰 / 优先级） | 无 | ❌ 全留 vs 截断，无价值分层 |
| 巩固（经历 → 经验） | compaction | ❌ compaction 是截断不是巩固 |

**一句话现状**：系统像一个**记性极好但从不回忆、也不认识用户的秘书**——会做事（skill）、存得下事（日志），但不会检索、不认识人、不提炼经验。

---

## 2. 补齐蓝图（按依赖排序，共五项）

### ① 语义记忆层：用户事实（先行，收益最高）
持久化「用户档案 + 决策记录」（偏好、背景、历史结论）。主会话每轮自动装载——解决"重启失忆、每次重新认识用户"。
→ 是所有其他记忆的**底座**：事实怎么存、怎么装载，流程/情景都复用这套机制。

### ② 流程性记忆层：SOP（与①共享机制）
主会话完成一类任务后，把执行过的多步过程凝练为**流程条目**（触发场景 → 步骤序列 → 产出标准 → 常见坑），按①的事实层机制持久化，下次同类任务直接调出。补上"情境绑定"与"流程进化"（成功执行后更新条目）。

### ③ 情景索引层：可检索回忆
给会话日志加轻量事件索引（主题 / 实体 / 结论提取），让"回忆上周那次订单重构"从碰运气变成可查询。主会话的 800 字摘要机制扩展为通用索引。

### ④ 巩固管道（依赖①②③）
定期把完成的对话 / 委派 / 流程执行**凝练成经验条目**写回①的事实层——compaction 是续命，巩固才是"经历 → 记忆"的转化。让系统"越用越懂用户"。

### ⑤ 前瞻记忆层：跨会话待办（依赖①）
把 goals 扩展为持久化待办清单，主会话可汇报"还有三件事没完成"。属于"记得要做的事"。

## 3. 落地形态（落在主会话身上）

```
主会话 = 记忆中枢
├─ 用户事实层  (①)  每轮自动装载 → "认识你"
├─ 流程库      (②)  任务完成后沉淀 SOP → "会做事"
├─ 情景索引    (③)  按主题/时间检索历史 → "记得事"
├─ 经验巩固    (④)  定期提炼写回事实层 → "越来越懂"
└─ 前瞻待办    (⑤)  跨会话持久目标 → "记得要做"
```

---

## 4. 关键设计决策

| 决策点 | 决定 | 理由 |
|------|------|------|
| 事实存放载体 | 独立 JSONL 文件 `~/.dsh/main-session/memory/user-facts.jsonl` | settings 是配置语义（schema 校验、UI 表单、热重载），用户事实是自由文本 + 持续追加，混入会让 settings.yaml 膨胀成日志 |
| 装载时机 | 主会话每轮 prompt 段注入（`systemPrompt.section`，text 为 provider 函数，order 55 紧邻 persona） | 复用 persona 机制；provider 每轮装配时求值，写后自动生效 |
| 事实类型 | profile / preference / decision / background 四类 | 静态档案与动态决策分开渲染 |
| 更新方式 | `memory_write` / `memory_read` 两个主会话专属工具 | 与 workspace_* 同模式，仅主 agent scope 可见 |
| 同 key 覆盖 | JSONL 追加保留全部历史；读时按 key 取最新 | 决策历史可追溯，无需重写文件 |
| 写入时机 | 模型判断（persona 规则引导），不自动抓取 | 避免记录一次性闲聊 |
| 刷新机制 | 存储层 `onWrite` 订阅 → prompt 段失效并重渲染 | 写后下一轮即见，无需重启 |
